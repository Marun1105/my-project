# Climby — product review, September 2026

Every screen, in both themes and both languages, against a local backend on a
clean browser profile; every user-facing string; the console; the network
tab; the test suite; the shape of the code. Findings are ranked by what they
cost a user, not by how hard they are to fix.

Three defects and four copy drifts were fixed while reviewing. The rest is
the list.

---

## Fixed in this pass

**Rope Team said "Loading…" forever.** Two lists on that screen shared one
stale-response counter; the second request always outran the first, so the
students list decided it was stale and never drew. Every student who opened
the screen saw a spinner over a `200 []`. Per-list counters now.

**Sign-in was five `<div>`s.** Password managers key their save-and-fill
prompts off a real `<form>` with a submit button, and Chrome said so in the
console on every load. Now real forms: Enter reaches the button natively, the
manager offers to remember the login, and nothing navigates.

**README was in Bulgarian** for an English-first product on a public repo.
Now English, and describing the app as it is today.

One finding was withdrawn: six `401`s on load turned out to be a stale token
in the reviewer's own profile. A true guest makes zero API calls. The app
handled the stale token correctly.

## 1. Defects

Things that are wrong, in the order they hurt.

### 1.1 The tutor knows nothing about you — *done, 20 Sept*

The ClimbAI screen — the front door — is identical on day 1 and day 100: four
cards and 55% empty space. No "continue where you left off", no last question,
no streak, no today's route. The streak *exists* (`focus.js` computes it) but
lives two clicks away on Ascent, where nobody goes unless they already use
the timer.

This is the single biggest lever in the app. Every returning-user pattern
that works — Duolingo's home, GitHub's contribution graph, Strava's feed —
works by making the first screen *yours*. See §4.

### 1.2 Rope Team shows both roles to everyone — *done, 20 Sept*

A student sees "Parent view… enter the code from your student" *and* "Give a
parent access". A parent sees "Create a code and give it to your parent". The
empty state literally tells a student "Ask your child for a code." The account
has a role; the screen should show one half.

### 1.3 "Plan help" on an empty Route — *done, 20 Sept*

The AI planner button is the most prominent thing on the screen — violet
gradient, full width — and on an empty list it can only answer "there are no
tasks". A primary CTA that cannot succeed. Hide it until there is something to
plan, or turn it into the empty state's suggestion ("Add two tasks and I'll
order them").

### 1.4 No way to leave, and no way to take your data — *done, 21 Sept*

`auth.py` has eleven routes and none of them delete an account, export data,
or change a password while signed in. For a children's app in the EU this is
not polish; a parent can ask for erasure and portability and today the only
answer is a database query by hand.

### 1.5 The rate limit is still per process

Keyed by account now (fixed on 8 September), but the counters live in the
memory of each Render worker. The real quota is *N × workers*, reset on every
deploy. Fine as a brake against a bot; wrong as a quota. It belongs in the
database.

### 1.6 No cap on what the AI can cost

1500 tokens a call, 12 calls an hour per account, 20 plans an hour, and
nothing global. A hundred enthusiastic students in exam week is a bill with
no ceiling. One counter in the database and one number in the environment.

### 1.7 The only test harness is Python

221 tests, and not one runs JavaScript. The `Loading…` bug above was a pure
frontend logic error that no static check could see. A minimal `node --test`
harness for `net.js`, `family.js` list rendering and the sequence counters
would have caught it in a second.

## 2. Copy

The English is good — warm without being cute, specific, and it says what
will happen. Six strings had drifted — four found by hand, two more by the
automated review *after* this document claimed all were fixed. All six are
fixed in both languages, and the retired names are now in
`test_frontend_checks.py` so the pattern can't recur silently: a feature
gets renamed and the strings that *mention* it are missed.

| Where | Says | Should say |
|---|---|---|
| Summited, tab | *Questions to the teacher* | *Questions to ClimbAI* — the teacher tab was renamed weeks ago |
| Rope Team, help box | *questions to the teacher stays private* | *questions to ClimbAI* |
| Ascent, help box | *How the focus camera works* | *How Ascent works* — the screen is called Ascent |
| ClimbAI, past-paper card | *Real NVO and matura exams* | English users don't know these words. *Real national exam papers (НВО, матура)* |
| Summited, empty state | *scan something in the Teacher tab* | *on the ClimbAI screen* — found by the automated review |
| Settings, no phone | *link one from the Teacher tab* | *from the ClimbAI screen* — same |

And one structural note: the help boxes are long. Three lines of explanation
above the content on every screen, every visit until dismissed. The first
sentence of each is enough; the rest belongs behind the `?`.

## 3. Design

The aurora-and-glass pass is genuinely good. Depth, restraint with colour,
the violet meaning exactly one thing. What's left:

**Empty vertical space.** ClimbAI, Ascent and Rope Team each use the top
third of a 900px viewport. The watermark fills the rest, and a watermark is
what you put where there is nothing. See §1.1 — the fix is content, not
layout.

**Two input styles.** The Route's inputs are dark and quiet; Rope Team's and
Base Camp's "code" inputs are a grey filled box with a visible border. Same
component, two skins.

**The Ascent ring.** The progress ring shows a three-quarter arc while the
timer is off. A ring that says 75% when nothing is running is a ring that
lies. Empty until there is a session.

**The tagline wraps.** *CLIMB YOUR WAY TO SUCCESS* breaks onto two lines in
the sidebar at every width. Either a shorter line for that spot or let it go
— the name is enough there.

**Ascent under ClimbAI.** The timer is grouped as a child of the tutor in the
sidebar. It's deliberate (`nav-group`), but a study timer isn't a sub-feature
of the AI. Worth a second look now that there are six screens.

## 4. Behavioural design — what works for learning

You asked for psychological tricks. Here is what the evidence supports, and
then the line I'd draw, because this is an app for children and some tricks
that grow numbers damage the people the numbers are made of.

### Do these

**Make the first screen a mirror.** *"Yesterday: 2 problems, 31 minutes.
Today: 1 task due."* One line at the top of ClimbAI. This is the whole
"endowed progress" effect — people finish what looks already started — and it
costs one API call you already make.

**Streak with grace.** Show the streak on the home screen, and let one missed
day not break it (a "rest day" a week). Streaks work because of loss
aversion; streaks *without* grace work until the first missed day and then
the person quits entirely, because the thing they were protecting is gone.
Duolingo added streak freezes for exactly this reason and retention went up.

**Name the next step, not the goal.** "Do your homework" is a goal. "Open
the Route" is a step. Implementation intentions — *when X, I will Y* — reliably
raise follow-through (Gollwitzer & Sheeran's meta-analysis puts the effect at
medium-to-large). The empty Route should say: *Add tomorrow's homework now;
you'll see it here first thing.*

**Celebrate the finish, briefly.** When a task is checked off, a half-second
of motion and one line: *Summited. 3 this week.* Not confetti. Not a modal.
The reward should be smaller than the work.

**Starter questions in the chat.** An empty chat with a blinking cursor is a
blank page, and blank pages stop children. Three chips: *What is a prime
number?*, *Explain fractions*, *Check my answer*. Removes the first-move
cost.

**Let the tutor remember.** *"Last time you asked about fractions — want to
try one more?"* Recency is the cheapest personalisation there is, and it
signals that the thing on the other side noticed.

**Show the parent the student's effort, not the student's failures.** Rope
Team already shows numbers only. Frame them as effort: *31 minutes, 3 days in
a row* rather than *2 overdue*. A parent who sees effort praises; a parent
who sees overdue nags; the child stops using the app that got them nagged.

### Don't do these

- **Fake urgency.** No countdowns, no "3 students in your class already did
  this", no "you're falling behind".
- **Shame-based streaks.** No "you lost your 12-day streak 😢". Reset quietly.
- **Notifications designed to interrupt.** One optional reminder at a time
  the student chose, and nothing else.
- **Variable rewards.** No loot, no random badges. The reward is the
  understanding; the app's job is to make that visible, not to compete with
  it.
- **Fake social proof.** No invented testimonials, no inflated counts.

These are not just ethics. Children notice manipulation faster than adults
and forgive it less; every one of these mechanisms trades long-term trust for
a short-term number, and the parent who installs the app is watching.

## 5. Marketing — honestly

**The blue screen is your biggest funnel loss.** *"Windows protected your PC"*
on first install, with the escape hidden behind *More info*. Most parents
stop there. Nothing else on this list matters as much as this.

What actually removes it, checked against Microsoft's current guidance
(their SmartScreen page, updated May 2026): **only the Microsoft Store.**
Store apps are re-signed by Microsoft and never show the warning. A
certificate of any kind — OV or EV — no longer bypasses SmartScreen; Microsoft
says so in as many words. A signed app still warns on first download, with
the publisher's name shown, until weeks of clean installs build reputation,
which then carries across versions signed with the same certificate.

So, in order: (1) an individual Store developer account is a one-time $19
and electron-builder already targets `appx`; the Store also takes over
updates. (2) Failing that, sign anyway so reputation can accumulate — Certum's
open-source certificate is about €25/year for individuals, and Climby's repo
is public, though its terms forbid commercial distribution, which matters if
the parent dashboard is ever paid. Azure's own signing service isn't open to
individuals outside the US and Canada. (3) Either way, today: a 15-second GIF
on the download page showing the two clicks.

**There is no website.** The only place Climby exists is a GitHub Releases
page. A parent cannot find it, a teacher cannot link to it, and a search for
"AI homework help Bulgaria" finds nothing. One page: what it does, the
privacy promise in plain words, a screenshot, a download button. Publishing
the frontend as a web app (it already runs in a browser) would double as the
landing page.

**The positioning is the anti-cheating angle.** Every AI homework tool on
earth is sold as "get answers". Climby's default is hints, it holds back the
solution, and it says so. That is the sentence: *The tutor that doesn't do it
for you.* Parents and teachers are the buyers and that sentence is what they
are afraid of and what they are looking for. Lead with it.

**Teachers are the distribution.** One teacher creating a Base Camp class
brings thirty students with a code. That is the viral loop, and it already
exists. Make the class code shareable as a link and a printable card, and
write the one-page teacher guide.

**Exam season is the calendar.** The past-papers feature is the wedge:
НВО in June, матура in May, and every parent in the country searching for
"НВО 7 клас подготовка" in April. Be the answer to that search, that month.

**Privacy is a feature, say it in three lines.** *Photos aren't kept. Parents
see numbers, never questions. Nothing about your face leaves the device.*
That is a stronger promise than any competitor makes, and it's true.

**Name the price now.** Free for students, always; the parent dashboard or
the class tools are the thing worth paying for, later. Deciding this early
shapes what gets built.

## 6. Engineering health

- 221 tests, all Python, ~110 seconds. Good coverage of auth, devices,
  classes, OAuth. Thin on tasks, scans, focus. Zero JavaScript tests (§1.7).
- `style.css` is past 2500 lines. It's holding, but it's where the next
  visual regression hides. Split by screen.
- The database is still the free-tier question. Neon was chosen; confirm
  it's done and that a dump runs on a schedule. Nothing has been backed up
  yet.
- Two old GitHub tokens still want revoking.
- `tutor.py` is a Bulgarian CLI experiment that isn't wired to anything.
  Delete it or move it to `scripts/`.
